# 아이맥스 1열 — 설계

/ 2026-08-10

웹캠 영상을 IMAX 스크린에 걸고, 그 상영관 **1열 좌석에서 올려다본 시점**으로
실시간 렌더한다. "오디세이 아이맥스 1열" 밈을 그대로 체험하게 만드는 것이 목적이다.

## 무엇을 만드는가

- 경로: `/playground/imax-front-row`, 제목 "IMAX 1열에서 본 내 얼굴"
- 사이트 레이아웃 안에 두지 않는다. 화면을 통째로 덮는다 — 상영관은 시야를
  다 먹어야 성립한다.
- 실시간 화면만. 촬영·녹화·저장·전송 없음. 영상도 사진도 브라우저 밖으로 나가지 않는다.
- 스크린에 걸 그림은 **카메라 또는 사진 파일**. 사진은 파일 선택·드래그앤드롭·
  붙여넣기 셋 다 받는다. 사진만 볼 사람에게 카메라 권한을 묻지 않는다.
- 좌석은 1열 정중앙 고정. 대신 **고개는 돌린다**(드래그 / 자이로).
- 얼굴만 잘라내지 않는다. 웹캠 프레임 전체를 1.43:1로 센터 크롭해 스크린에 건다.
  방 전체가 IMAX에 걸리는 편이 더 웃기고, 얼굴 검출 의존성이 통째로 사라진다.

## 왜 WebGL인가

왜곡을 흉내내지 않고 **실제 기하로 만든다.** 곡면 스크린을 3D 공간에 세우고
1열 눈높이에 카메라를 두면, 사다리꼴 왜곡·좌우 감김·아래는 거대하고 위는
좁아지는 원근이 전부 투영의 결과로 따라 나온다.

대안이었던 Canvas 2D 가로 스트립은 세로 사다리꼴만 되고 좌우 곡률이 안 나온다.
CSS `rotateX`는 곡률이 0이다. 1열의 정체가 "화면이 나를 감싼다"인데
그걸 못 만들면 만들 이유가 없다.

## 극장 수치

실제 IMAX GT 규격에서 가져왔다.

| 항목 | 값 |
| --- | --- |
| 스크린 | 폭 22m(호 길이) × 높이 16m, 1.43:1 |
| 하단 모서리 | 바닥에서 1.0m |
| 수평 곡률 반경 | 45m, 관객 쪽으로 오목 |
| 상단 기울기 | 3°, 위쪽이 관객 쪽으로 |
| 눈 위치 | 스크린 중앙 평면에서 4.5m, 높이 1.4m |
| 시야각 | 세로 66°, 기본 앙각 +42° |

여기서 따라 나오는 것:

- 스크린 꼭대기를 보려면 **위로 76.8°**를 올려다봐야 한다. 목이 꺾이는 각도.
- 스크린 좌우 끝은 시선 중심에서 ±75.9°. 가로 화각(16:9에서 약 129°)을 넘어
  **프레임 밖으로 넘친다.** "한눈에 안 들어온다"가 1열의 정체다.
- 세로로는 -5.1°부터 +76.8°까지 82°를 차지해, 화각 66°를 **위아래로 넘친다.**
  스크린 끝이 안 보이는 게 정상이다.

화각을 100°로 잡았다가 66°로 좁혔다. 넓은 화각은 «다 보이게» 만들지만 그 대가로
전부 작아진다. 스크린이 프레임 안에 얌전히 들어오는 순간 그건 1열이 아니라
큰 화면을 멀리서 보는 그림이다. 대신 바닥·무대턱·측벽은 기본 시야에서 밀려나므로,
앙각 하한을 -6°까지 열어 고개를 내리면 상영관이 그대로 나오게 했다.

곡률 반경은 이 페이지에서 가장 취향을 타는 값이다. 처음 26m는 좌우 끝이 중앙보다
2.3m나 앞으로 나와 스크린이 아니라 그릇처럼 보였다. 45m면 1.3m — 휜 게 보이되
평면감이 남는다.

## 모듈

```
src/app/playground/imax-front-row/
  page.tsx          메타데이터. 정적 프리렌더라 runtime 표기 없음
  ImaxFrontRow.tsx  웹캠 취득, rAF 루프, 드래그·자이로, 권한 게이트
  screen.ts       ★ 곡면 스크린 기하: 표면 위 점, 메시 생성, 센터 크롭 UV
  seat.ts         ★ 좌석 시점: 뷰·투영 행렬, 시선 클램프, 앙각 계산
  ambience.ts     ★ 상영관 분위기: 게이트 위블, 플리커, 스크린 스필 색
  gl.ts             셰이더 컴파일·프로그램·텍스처 얇은 래퍼
  *.test.ts       ★ 세 모듈
```

★ 순수 함수. 이 프로젝트에서 실제로 깨지는 건 기하라서, 테스트도 "돌아간다"가
아니라 **1열이 맞는지**를 확인한다.

- 스크린 꼭대기 앙각이 65°를 넘는다 — 안 넘으면 1열이 아니다
- 투영된 스크린 하단 폭 > 상단 폭 — 사다리꼴이 뒤집히지 않았는지
- 좌우 끝 정점이 중앙보다 관객 쪽에 있다 — 곡률 방향
- 모든 정점이 카메라 앞에 있다 — 90°를 넘으면 투영이 발산한다
- 스크린이 위아래로 프레임을 넘친다 — 다 보이면 1열이 아니다
- 화면 한복판에는 늘 스크린이 있다 — 넘치게 만들다 조준이 어긋나면 벽이 걸린다
- 시선 클램프가 스크린 밖으로 안 나간다
- 크롭 UV가 원본 비율과 무관하게 1.43:1을 유지한다

## 렌더 패스

캔버스 하나에 두 번 그린다. DOM 오버레이를 섞지 않는 이유는 빛 번짐이 따로 놀아서다.

1. **상영관** — 전체화면 쿼드. 카메라 광선 방향으로 바닥·무대턱·스피커 그릴·
   측벽 패널·천장을 해석적으로 칠한다. 전부 스크린 스필 색으로 물든다.
   EXIT 초록 등 두 개도 여기서 광선 방향으로 얹는다.
2. **스크린** — 64×48 곡면 메시에 카메라/사진 텍스처. 카메라만 셀피처럼 좌우
   반전하고 사진은 그대로 건다 — 사진까지 뒤집으면 글자가 죄다 뒤집힌다.
   게이트 위블은 카메라가 아니라 **스크린 모델 행렬**에 건다. 실제 영사기가
   그렇게 흔들린다.
필름 그레인·비네트는 세 번째 패스를 두지 않고 두 셰이더가 같은 `filmGrade`를
마지막에 부른다. 각 픽셀은 깊이 테스트로 둘 중 한쪽만 쓰므로 결과가 같으면서
프레임버퍼가 필요 없다.

스크린 스필 색은 8×8로 줄인 웹캠 프레임의 평균색이다. 매 프레임 하지 않고
6프레임에 한 번 갱신한다.

## 카메라와 사진을 한 가지로

렌더러는 그림이 카메라에서 왔는지 파일에서 왔는지 모른다. `Source` 하나로
받는다 — 무엇을 올릴지, 얼마나 큰지, 바뀌었는지(`revision`), 뒤집을지.
`revision`이 그대로면 텍스처를 다시 올리지 않으므로, 60fps 렌더에서 30fps
카메라는 절반을 건너뛰고 사진은 사실상 한 번만 올라간다.

모드를 바꾸는 일은 매 프레임 그림을 집어오는 함수 하나를 갈아끼우는 것이
전부다. 상영 중에 사진을 바꿔도 렌더러를 다시 세우지 않는다 — 껐다 켜면
화면이 검게 한 번 끊기는데, 사진 바꾸기는 연달아 하는 일이라 거슬린다.

## 권한과 실패

`gaebari-glare`의 흐름을 따른다. 시작 버튼 → `getUserMedia` → 거부·미지원이면
전용 안내 패널. WebGL2를 못 얻는 경우도 같은 자리에서 안내한다.
페이지를 떠나면 트랙을 확실히 끈다.
