# 오늘의 찜질방 — 설계

날씨를 숫자 대신 찜질방 방 이름으로 알려주는 플레이그라운드 페이지.
"오늘 서울은 습식사우나" 한 문장이 이 프로젝트의 전부다.

## 화면

아이폰 날씨 앱을 그대로 따른다. 화면을 통째로 덮고, 판정된 방을 찍은 사진이
배경 끝까지 간다. 사이트의 머리말·꼬리말은 흰 배경 위에 설계돼 있어서 사진 위에
얹으면 읽히지 않으므로 이 라우트에서는 덮어 가린다 — 대신 왼쪽 위에 돌아가는 길을 둔다.

위에서 아래로: 도시 이름 → 아주 얇고 큰 체감온도 → 방 이름 → 한 줄 카피 →
최고·최저. 그 아래에 반투명 유리 카드로 시간별 띠와 체감온도·습도 타일.

시간별 띠는 지금 시각을 첫 칸으로 24시간을 보여준다. 날씨 아이콘 자리에는
그 시각의 방 사진 조각이 들어간다 — 배경에서 이미 쓰는 사진이라 새로 받을 게 없고,
"3시에는 저 방"이 글자보다 먼저 읽힌다.

## 방 사진

아홉 개 방을 각각 실사 사진으로 만들어 `public/playground/jjimjilbang/`에 둔다.
Higgsfield MCP(nano_banana_2, 9:16, 2K)로 만들고 1080px 폭 WebP로 줄여 넣는다 —
원본 PNG 아홉 장은 83MB라 그대로는 못 쓴다. 줄인 뒤 전부 합쳐 1.4MB다.

사람이 없는 빈 방으로, 위쪽이 어둡게 잡히도록 프롬프트를 쓴다. 그 위에 다시
위아래를 누르는 검은 그라데이션 막을 깔아야 흰 글자가 어떤 사진에서도 읽힌다.

## 데이터

**기상청 단기예보 조회서비스**(공공데이터포털)를 쓴다. 두 엔드포인트를 부른다.

- `getUltraSrtNcst` (초단기실황) — 지금 관측된 기온·습도·풍속. 맨 위 큰 숫자에 쓴다.
- `getVilageFcst` (단기예보) — 시간별 예보. 아래 띠에 쓴다.

실황을 따로 부르는 건 화면이 "지금 서울은"이라고 말하기 때문이다. 예보값으로 그
자리를 채우면 예측을 관측인 척 보여주게 된다. 실황이 실패하면 예보 첫 칸으로 물러난다.

**Open-Meteo를 쓰지 않는 이유.** 무료 등급 약관이 "광고를 게재하는 웹사이트"를
상업적 이용으로 규정하고 금지한다. 이 사이트는 AdSense를 싣는다. 기상청 공공데이터는
공공누리 제1유형이라 출처만 표시하면 된다.

### 직접 해야 하는 계산 둘

**체감온도.** 기상청은 기온·습도·풍속만 주고 체감온도를 주지 않는데, 방 판정이 거기
걸려 있다. 여름은 습구온도(Stull 추정식)를 거치는 기상청 개정식, 겨울은 바람 냉각식을
쓰고, 둘 다 아닌 구간(10~20°C, 또는 바람 없는 추운 날)은 기온을 그대로 쓴다 — 없는
값을 지어내는 것보다 정직하다.

Stull 식의 arctan은 라디안이다. 도(°)로 넣으면 첫 항이 기온의 57배가 되어 수천 단위
값이 나온다. "습도 100%면 습구온도가 기온과 같다"는 검사가 이걸 잡는다.

**격자 좌표.** 기상청은 위경도를 받지 않고 5km 격자 (nx, ny)만 받는다. 람베르트
정각원추도법 변환을 옮겨 둔다. 상수는 기상청이 못박은 값이라 고칠 수 있는 숫자가 아니다.

### 서버 라우트가 필요한 이유

인증키가 비밀이라 브라우저에서 부를 수 없다. `/api/jjimjilbang`이 키를 쥐고
기상청을 부른다. 발표 주기가 실황 1시간·예보 3시간이라 그 사이는 캐시한다.

기상청은 실패해도 HTTP 200을 준다. 인증 실패도 격자 밖 좌표도 200에 `resultCode`만
다르게 실려 오므로 응답 본문을 직접 봐야 한다.

### 체감온도는 만들 때 한 번만 반올림한다

화면은 정수로 보여주는데 판정을 원래 값으로 하면 경계에서 어긋난다. 서울이 34.97°일 때
"35°"라 써 놓고 35° 미만이라 건식사우나로 갔다 — 판정표에는 35°부터 불가마인데도.

## 방 판정

체감온도 밴드 × 습도 60% 기준으로 갈린다.

| 체감온도 | 습도 60% 미만 | 습도 60% 이상 |
| --- | --- | --- |
| 35° 이상 | 🔥 불가마 | 🌋 열탕지옥 |
| 28° 이상 | 🟠 건식사우나 | 💦 습식사우나 |
| 20° 이상 | 🟤 황토방 | 🪨 소금방 |
| 10° 이상 | ❄️ 수면실 | 🌫️ 안개방 |
| 10° 미만 | 🧊 얼음방 | 🧊 얼음방 |

비와 눈은 별도 축으로 두지 않는다. 습도에 이미 나타나기 때문이다.

이 표는 `rooms.ts`의 순수 함수 `roomFor(apparent, humidity)` 하나로 구현한다.
네트워크도 React도 모르는 함수라 경계값을 그대로 테스트한다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `rooms.ts` | 방 정의(이름·이모지·색·카피)와 판정 함수 |
| `weather.ts` | 화면과 서버 사이의 타입, 우리 라우트를 부르는 fetch |
| `kma.ts` | 기상청 발표 시각 계산과 응답 파싱 |
| `feelsLike.ts` | 체감온도(여름·겨울 식, 습구온도) |
| `grid.ts` | 위경도 → 기상청 5km 격자 |
| `api/jjimjilbang/route.ts` | 인증키를 쥔 서버 중계와 캐시 |
| `cities.ts` | 주요 도시 좌표와 최근접 찾기 |
| `VerdictCard.tsx` | 도시·온도·방 이름 머리 부분. 상태 없음 |
| `Timeline.tsx` | 시간별 유리 카드. 상태 없음 |
| `backdrop.module.css` | 사진 교체 페이드와 스크롤바 감추기 |
| `JjimjilbangWeather.tsx` | 클라이언트 진입점. 위치·로딩·에러 상태만 담당 |
| `page.tsx` | 서버 컴포넌트. 메타데이터 |

파싱과 fetch를 나눠 둔다. 파싱은 순수 함수라 테스트할 수 있고, fetch는 감쌀 게 없다.

## 실패했을 때

- **위치 거절/실패** — 경고 없이 서울로 간다. 도시 선택기는 원래 자리에 그대로 있으므로
  사용자는 막힌 느낌 없이 다른 도시를 고를 수 있다.
- **날씨 요청 실패** — 판정 카드 자리에 "지금은 탈의실" 상태와 다시 시도 버튼.
- **로딩 중** — 카드 골격만 은은히 깜빡인다.

## 테스트

- `rooms.test.ts` — 모든 밴드 경계값(10/20/28/35°, 습도 60%)과 얼음방의 습도 무시
- `cities.test.ts` — 좌표에서 최근접 도시, 목록 밖 좌표
- `weather.test.ts` — `fromNow`가 지금 시각을 첫 칸으로 자르고 자정을 넘어가는지
- `grid.test.ts` — 서울(60,127)·부산(98,76)·제주(53,38)가 기상청 배포 격자와 같은지
- `feelsLike.test.ts` — 습도 100%에서 습구온도=기온, 식이 갈리는 경계값
- `kma.test.ts` — 발표 시각(40분·10분 규칙, 자정 넘김), 시각별 묶기, 200에 실린 오류

## 하지 않는 것

주간 예보, 알림, 즐겨찾기, 결과 저장, 공유 이미지 생성. 한 문장을 잘 보여주는 것 하나만 한다.

## 배포할 때

`KMA_SERVICE_KEY`를 배포 환경에도 넣어야 한다. 없으면 라우트가 500을 낸다.
포털이 주는 **일반 인증키(Decoding)** 쪽을 넣는다 — 인코딩된 키를 넣으면
`URLSearchParams`가 한 번 더 인코딩해서 인증이 깨진다.
