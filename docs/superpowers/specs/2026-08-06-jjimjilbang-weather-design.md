# 오늘의 찜질방 — 설계

날씨를 숫자 대신 찜질방 방 이름으로 알려주는 플레이그라운드 페이지.
"오늘 서울은 습식사우나" 한 문장이 이 프로젝트의 전부다.

## 화면

한 페이지에 두 덩어리.

1. **판정 카드** — 지금 이 자리가 어떤 방인지. 방 이름, 이모지, 체감온도, 습도, 한 줄 카피.
2. **시간대 띠** — 오늘 하루를 3시간 간격으로 늘어놓고 각 칸이 어떤 방인지. 지금 시각에 표시.

배경 전체가 판정된 방의 색으로 물든다. 방이 바뀌면 화면 색이 바뀐다 — 스크린샷 한 장으로 공유될 만한 화면을 목표로 한다.

## 데이터

Open-Meteo `forecast` 한 번 호출로 판정 카드와 타임라인을 모두 채운다.

```
https://api.open-meteo.com/v1/forecast
  ?latitude=..&longitude=..
  &current=temperature_2m,relative_humidity_2m,apparent_temperature
  &hourly=temperature_2m,relative_humidity_2m,apparent_temperature
  &timezone=Asia%2FSeoul&forecast_days=1
```

API 키가 없고 브라우저에서 직접 부를 수 있다. 서버 라우트도 환경변수도 만들지 않는다.
기상청 단기예보 API는 키 발급과 격자 좌표 변환이 필요해서 쓰지 않는다.

위치는 브라우저 geolocation. 좌표를 도시 이름으로 바꿀 때 역지오코딩 API를 부르지 않고
내장 도시 목록 중 가장 가까운 곳을 고른다 — 요청 하나를 덜 쓰고 한국어 이름이 보장된다.

## 방 판정

체감온도 밴드 × 습도 60% 기준으로 갈린다.

| 체감온도 | 습도 60% 미만 | 습도 60% 이상 |
| --- | --- | --- |
| 35° 이상 | 🔥 불가마 | 🌋 열탕지옥 |
| 28° 이상 | 🟠 건식사우나 | 💦 습식사우나 |
| 20° 이상 | 🟤 황토방 | 🪨 소금방 |
| 10° 이상 | ❄️ 수면실 | 🌫️ 안개방 |
| 10° 미만 | 🧊 얼음방 | 🧊 얼음방 |

비와 눈은 별도 축으로 두지 않는다. 습도에 이미 나타나기 때문이다.

이 표는 `rooms.ts`의 순수 함수 `roomFor(apparent, humidity)` 하나로 구현한다.
네트워크도 React도 모르는 함수라 경계값을 그대로 테스트한다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `rooms.ts` | 방 정의(이름·이모지·색·카피)와 판정 함수 |
| `weather.ts` | Open-Meteo 응답을 도메인 타입으로 바꾸는 파싱, 그리고 fetch |
| `cities.ts` | 주요 도시 좌표와 최근접 찾기 |
| `VerdictCard.tsx` | 판정 카드 표시. 상태 없음 |
| `Timeline.tsx` | 시간대 띠 표시. 상태 없음 |
| `JjimjilbangWeather.tsx` | 클라이언트 진입점. 위치·로딩·에러 상태만 담당 |
| `page.tsx` | 서버 컴포넌트. 메타데이터 |

파싱과 fetch를 나눠 둔다. 파싱은 순수 함수라 테스트할 수 있고, fetch는 감쌀 게 없다.

## 실패했을 때

- **위치 거절/실패** — 경고 없이 서울로 간다. 도시 선택기는 원래 자리에 그대로 있으므로
  사용자는 막힌 느낌 없이 다른 도시를 고를 수 있다.
- **날씨 요청 실패** — 판정 카드 자리에 "지금은 탈의실" 상태와 다시 시도 버튼.
- **로딩 중** — 카드 골격만 은은히 깜빡인다.

## 테스트

- `rooms.test.ts` — 모든 밴드 경계값(10/20/28/35°, 습도 60%)과 얼음방의 습도 무시
- `weather.test.ts` — 정상 응답 파싱, 필드가 빠진 응답에서 오류
- `cities.test.ts` — 좌표에서 최근접 도시, 목록 밖 좌표

## 하지 않는 것

주간 예보, 알림, 즐겨찾기, 결과 저장, 공유 이미지 생성. 한 문장을 잘 보여주는 것 하나만 한다.
