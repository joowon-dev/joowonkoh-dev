# 같이 걸은 지도 — 설계

두 사람의 구글 타임라인을 한 지도에 겹쳐 재생하고, 서로 가까이 있었던 순간을 찾아
영상으로 뽑는 도구. `/playground/together-map`.

레퍼런스는 [ahn-lab.org/google-timeline-visualizer](https://ahn-lab.org/google-timeline-visualizer/)다.
그쪽은 한 사람의 이동을 영상으로 만든다. 이쪽은 **두 사람을 겹쳐서, 만난 순간을 찾는 것**이
목적이다. 나머지 옵션은 레퍼런스를 그대로 따라간다.

## 왜 만드는가

한 사람의 이동 궤적은 예쁘긴 해도 본인만 재미있다. 두 사람을 겹치는 순간
«이 날 여기서 만났네»가 나오고, 그건 둘이 같이 볼 이유가 된다. 커플이든 친구든
같은 기간의 기록을 각자 갖고 있다는 점이 이 도구의 유일한 전제다.

## 제약

- **서버 없음.** 파일은 브라우저를 떠나지 않는다. 지도 타일 요청만 나간다.
- **새 의존성 없음.** Canvas 2D, MediaRecorder, fetch로 끝난다.
- **정적 페이지.** 서버에서 데이터를 가져오지 않으므로 `runtime = "edge"`가 필요 없다.
  빌드 후 `○`(static)으로 나오는지 확인한다.
- 기존 플레이그라운드 관례를 따른다 — 순수 함수 모듈 + 옆에 `.test.ts`,
  `page.tsx`는 메타데이터만, 상태는 `"use client"` 컴포넌트 하나에 모은다.

```
  MeetList.tsx       찾아낸 만남 목록

  sample.ts   .test  가상 여행 데이터 생성
  geo.ts      .test  거리 · 보간 · 웹 메르카토르 투영
  filter.ts   .test  정확도 · 이상치 필터
  meet.ts     .test  만난 순간 검출
  summary.ts  .test  마무리 통계 (횟수 · 함께한 시간 · 단골 자리 · 최장거리)

```

## 데이터 모델

```ts
/** 한 사람의 기록. 시간 오름차순. */
interface Track {
  id: "a" | "b";
  name: string;
  color: string;
  points: Point[];
}

interface Point {
  t: number;        // epoch ms
  lat: number;
  lon: number;
  /** 미터. 없으면 undefined — 필터에서 «모름»과 «정확함»을 구분해야 한다. */
  accuracy?: number;
  kind: "visit" | "path";
}

/** 두 사람이 가까이 있었던 한 구간. */
interface Meeting {
  start: number;
  end: number;
  lat: number;      // 구간의 중앙값 위치
  lon: number;
  /** 구간 중 가장 가까웠던 거리(m). */
  minDistance: number;
}
```

## 파서

구글은 같은 데이터를 세 가지 모양으로 뱉는다. 최상위 키를 보고 갈라낸다.

| | 안드로이드 기기 내보내기 | 아이폰 기기 내보내기 | 옛 Takeout |
|---|---|---|---|
| 최상위 | `{ semanticSegments: [...] }` | 배열 그 자체 | `{ locations: [...] }` |
| 방문 좌표 | `placeLocation.latLng` | `placeLocation` (문자열) | — |
| 좌표 표기 | `"37.5665°, 126.9780°"` | `"geo:37.5665,126.9780"` | `latitudeE7: 375665000` |
| 장소 ID | `placeId` | `placeID` | — |
| 거리 | 숫자 `3850` | 문자열 `"3850"` | — |
| 경로 점 시각 | ISO 8601 `time` | `durationMinutesOffsetFromStartTime` | `timestamp` |

세부 규칙:

- 좌표 문자열은 `°`·공백·`geo:` 접두사를 모두 걷어내고 숫자 두 개만 남긴다.
- 거리 필드는 숫자든 문자열이든 받는다.
- **`timelinePath`와 `activity`를 둘 다 더하지 않는다.** 같은 땅을 두 번 세게 된다.
  선을 그릴 때는 `timelinePath`를 쓰고, 거리 통계는 `activity`에서 가져온다.
- 형식을 못 알아보면 조용히 빈 배열을 주지 말고 **어떤 형식으로 보였는지 적어서 오류를 낸다.**
  사용자가 가진 파일이 왜 안 되는지 알 수 있어야 한다.

## 필터

`filter.ts`의 두 단계. 순서가 중요하다 — 정확도 먼저, 이상치 나중.

1. **정확도** — `accuracy`가 한계값(기본 200m)을 넘으면 버린다. `accuracy`가 없는 점은
   버리지 않는다. 옛 형식엔 이 필드가 아예 없어서, 버리면 전부 사라진다.
2. **이상치(보수적)** — 앞뒤 점과의 시간차로 필요한 이동 속도를 구해서
   **시속 900km를 넘으면** 그 점 하나를 버린다. 비행기보다 빠른 점은 GPS가 튄 것이다.
   연속으로 여러 점이 빠르면 실제 비행일 수 있으므로 버리지 않는다.

«원본 위치 데이터 사용»을 켜면 `rawSignals`까지 포함해서 점이 훨씬 촘촘해진다.
끄면 `semanticSegments`만 쓴다.

## 만난 순간 검출 — 이 도구의 핵심

두 트랙을 공통 5분 격자에 올려놓고 거리를 잰다.
**기본 100m 이내가 15분 이상 이어지면 만남 하나.** 둘 다 UI에서 조절한다.

여기에 틀리기 쉬운 지점이 둘 있다.

**기록 구멍을 건너뛰며 보간하지 않는다.** 앞뒤 점의 시간차가 30분을 넘으면 그 사이는
«위치를 모르는 구간»으로 두고 비운다. 이걸 안 하면 서울에서 부산까지 직선이 그어지고,
그 선이 상대 궤적을 스쳐 지나가면서 **있지도 않은 만남이 생긴다.** 검출기에서 제일 위험한 버그다.

**한 점이 튀어서 만남이 생기는 걸 막는다.** 최소 지속시간 15분이 이걸 대부분 걸러내지만,
필터 단계에서 먼저 걸러 두는 편이 확실하다.

만남 하나의 대표 위치는 평균이 아니라 **중앙값**으로 잡는다. 평균은 구간 끝에 붙은
이동 구간에 끌려간다.

## 화면 흐름

```
1. 시작        파일 두 개 고르기 | «가상 여행으로 해보기»
2. 동의        지도 타일 안내 → «이해했고 지도를 불러오겠습니다»
3. 설정        기간 · 필터 · 만남 기준 · 영상 옵션 + 찾아낸 만남 목록
4. 미리보기    캔버스 재생
5. 영상        MP4 만들기 → 진행률 → 다운로드 · 공유
```

동의 체크 전에는 타일을 한 장도 요청하지 않는다. 레퍼런스와 같은 규칙이다.

## 영상

전체 기간을 처음부터 끝까지 재생하고, 마지막 3초에 통계 카드가 뜬다.

재생 중에는 각 트랙의 최근 꼬리만 그린다. 전체를 계속 그리면 화면이 금방 실뭉치가 된다.
두 선이 100m 안으로 들어오면 그 자리에 링이 퍼지고 하단 카운터가 오른다.

마무리 카드에 넣는 것: 만난 횟수, 함께한 총 시간, 가장 자주 만난 자리, 가장 멀리
떨어져 있었던 거리와 그 날짜.

**카메라 세 모드**

- **고정 줌** — 전체 기간이 다 들어오는 한 화면. 카메라가 안 움직인다.
- **부드럽게 따라가기** — 두 사람이 다 들어오는 사각형을 구하고 거기로 천천히 따라간다.
- **역동적으로 따라가기** — 위와 같되 감쇠를 줄이고, 만남 순간에 살짝 줌인한다.

**저장** — `canvas.captureStream()` + `MediaRecorder`. `video/mp4`를 지원하면 mp4로,
아니면 webm으로 떨어뜨리고 화면에 어느 쪽인지 표시한다. 사파리는 mp4, 크롬은
브라우저 판마다 다르다. `isTypeSupported`로 런타임에 확인한다.

타일은 `crossOrigin="anonymous"`로 받는다. 이걸 빠뜨리면 캔버스가 오염되어
`captureStream`이 통째로 막힌다.

## 프라이버시

- 파일은 업로드되지 않는다. 타일 요청만 나가고, 그때 타일 서버가 대략적인 위치를
  알게 된다는 사실을 동의 화면에 그대로 적는다.
- **집 주변 가리기** — 반경을 정하면 그 안의 궤적이 흐려진다. 이 영상은 남에게
  보여주려고 만드는 것이라 집 좌표가 그대로 찍히면 곤란하다. 레퍼런스에는 없고
  2인용이라서 더 필요한 기능이다. 기본은 꺼짐.

## 가상 여행 샘플

파일이 없어도 바로 돌려볼 수 있어야 하고, 동시에 **파서 테스트 픽스처**로 쓴다.

가상의 두 사람이 3개월간 움직인 기록을 만든다.

- 평일엔 각자 다른 동네에서 출퇴근한다
- 주말마다 성수·홍대에서 만난다 — 만남이 잡혀야 하는 구간
- 한 번은 같이 부산에 다녀온다 — 장거리에서도 붙어 있는 구간
- 한 번은 한 명만 제주에 간다 — **만남이 잡히면 안 되는 구간**
- 기록 구멍과 튄 GPS 점을 일부러 섞는다 — 필터가 실제로 일하는지 보이게

같은 데이터를 안드로이드 모양과 아이폰 모양 양쪽으로 뽑아서 파서 테스트에 쓴다.
진짜 파일이 없는 상태에서 형식 오차를 줄이는 유일한 방법이다.

생성은 결정적이어야 한다 — 시드를 받는 의사난수를 쓰고, `Math.random()`은 쓰지 않는다.
그래야 테스트가 흔들리지 않는다. `_shared/random.ts`에 이미 있으면 그걸 쓴다.

## 테스트

`.test.ts`가 붙는 것은 순수 함수 모듈뿐이다. 캔버스와 MediaRecorder는 테스트하지 않는다.

- `parse` — 세 형식 각각, 좌표 표기 세 가지, 숫자/문자열 거리, 알 수 없는 형식의 오류
- `geo` — 아는 두 지점 사이 거리, 구멍을 건너뛰지 않는 보간, 투영 왕복
- `filter` — 정확도 경계값, `accuracy` 없는 점 보존, 튄 점 하나 제거, 연속 고속 보존
- `meet` — 만남 검출, 최소 지속시간 미달 기각, **구멍 너머 가짜 만남 기각**, 중앙값 위치
- `camera` — 두 점을 담는 사각형, 종횡비별 프레이밍
- `render` — 좌표→화면 변환, 꼬리 길이 계산
- `sample` — 같은 시드면 같은 결과, 제주 구간에서 만남 0건

## 안 하는 것

- 계정, 저장, 공유 링크. 새로고침하면 처음부터다.
- 세 명 이상. 색과 «만남»의 정의가 통째로 달라진다. 필요해지면 그때 다시 설계한다.
- 지도 검색이나 장소 이름 붙이기. 역지오코딩은 외부 요청이 늘고,
  «만난 자리»의 좌표가 남의 서버로 나간다.
