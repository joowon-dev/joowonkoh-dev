# 코인 푸셔 추첨기 (Coin Pusher) — 설계

작성일: 2026-07-28
경로: `/playground/coin-pusher`

## 1. 목적

참가자 이름을 붙여넣으면 오락실 코인 푸셔 기계 위에서 각자의 코인이 떨어지고, 푸셔에 밀려 가장 먼저 낭떠러지 아래로 떨어진 코인의 주인이 당첨되는 추첨기. 모임·회식·경품 추첨에서 화면을 띄워놓고 돌리는 용도.

기존 `/playground/paper-plane`이 만들어 둔 "센서·물리 기반 미니게임 + 순수 함수 물리 모듈 + vitest" 패턴을 이어간다.

## 2. 게임 흐름

상태 머신: `setup → dropping → pushing → result`

1. **setup** — 참가자 이름 입력. 줄바꿈 또는 쉼표 구분 텍스트를 붙여넣으면 칩 목록으로 파싱. 공백 제거, 중복 제거, 빈 문자열 제외.
2. START 시 판 위에 중립 코인을 랜덤 배치. 개수는 참가자 수에 비례.
3. **dropping** — 참가자 코인 전원이 랜덤한 지점·순서·초기 속도로 판 위에 낙하.
4. **pushing** — 푸셔가 앞뒤로 왕복하며 코인 더미를 민다. 중립 코인이 일정 간격으로 하나씩 추가 투입된다. 이 단계에서 돌발 이벤트가 확률적으로 발생하고, 경과 시간이 임계값을 넘으면 막판 스퍼트로 전환된다.
5. **result** — 첫 코인이 앞 낭떠러지 아래로 떨어지는 순간 슬로우모션 → 당첨자 발표.

**당첨 규칙:** 먼저 떨어진 코인 1명. 같은 프레임에 여러 코인이 낙하 조건을 만족하면 낙하선을 더 많이 넘어선(worldY가 더 큰) 코인이 승리한다. 부동소수점이 완전히 같은 경우는 배열 인덱스가 작은 쪽으로 결정론적으로 처리한다.

## 3. 시점과 렌더링

물리는 순수 2D 평면 `(x, y)`에서 계산하고, 렌더링 단계에서만 비스듬한 시점으로 왜곡한다.

- 화면 좌표: `screenY = worldY * PERSPECTIVE_SCALE` (초기값 0.55)
- 코인은 원 + 아래쪽으로 두께만큼 그린 실린더 옆면 + 바닥 그림자로 입체감 표현
- 앞 가장자리 아래로 떨어지는 구간은 물리 시뮬레이션에서 분리해 **순수 연출**로 처리 (회전하며 낙하)
- Canvas 2D, `devicePixelRatio` 대응
- 3D 라이브러리를 도입하지 않는다

## 4. 물리 — 자체 구현

### 근거
모든 코인이 동일 반지름의 원이라 필요한 충돌 처리는 원-원과 원-AABB뿐이다. Matter.js를 도입하면 번들이 늘고, 회전을 포함한 일반 강체 해법은 이 게임에 과하다. 종이비행기가 이미 순수 함수 물리 모듈 + vitest 패턴을 쓰고 있어 일관성도 맞다.

### 모델
- 코인: 위치 `(x, y)`, 속도 `(vx, vy)`, 질량, 반지름 동일, 회전은 무시
- 푸셔: 뒤에서 앞으로 왕복하는 이동 AABB
- 판: 좌·우·뒤 벽, 앞은 열린 낭떠러지

### 스텝
고정 타임스텝 `1/120초`를 누적기(accumulator)로 소비한다. 렌더 프레임레이트와 무관하게 결정론적이므로, 시드가 같으면 결과가 재현된다.

각 스텝 순서:
1. 푸셔 위치 갱신
2. 코인-코인 충돌: 위치 보정(penetration resolution) + 임펄스
3. 코인-벽, 코인-푸셔 충돌
4. 마찰 감쇠
5. 낙하 판정 (`y > FALL_LINE`)

### 성능
공간 해시 그리드로 브로드페이즈를 O(n)에 처리한다. 참가자 200명(코인 약 400개) 기준 60fps를 목표로 한다.

### 난수
시드 기반 PRNG(mulberry32 등)를 물리·이벤트 전 구간에서 사용한다. `Math.random()`을 직접 호출하지 않는다. 시드는 게임 시작 시 한 번 생성한다.

## 5. 랜덤 요소

### 5.1 초기 배치·투입 랜덤
- 중립 코인의 초기 좌표와 개수
- 참가자 코인의 낙하 순서, 낙하 지점, 초기 속도

### 5.2 특수 코인
**중립 코인에만** 부여한다.
- 황금 코인: 질량 2.5배. 더미를 강하게 밀어낸다.
- 스프링 코인: 접촉 시 반발 계수가 크게 올라가 코인을 튕겨낸다.

### 5.3 돌발 이벤트
`pushing` 단계에서 확률적으로 발생하며, 상단 배너로 표시된다.
- 진동: 전체 코인에 짧고 무작위한 임펄스
- 판 기울기: 일정 시간 동안 한쪽 방향 가속도 추가
- 푸셔 러시: 푸셔 왕복 속도 2배

### 5.4 막판 스퍼트
경과 45초 시점부터 푸셔 스트로크를 확대하고 중립 코인을 대량 투하해 교착을 강제로 깬다.

### 5.5 공정성
참가자 코인은 질량·반지름·마찰이 전부 동일하고, 초기 배치만 랜덤이다. 특수 능력은 중립 코인 몫이므로 특정 참가자가 구조적으로 유리해지지 않는다.

## 6. UI

- 상단 HUD: 남은 인원 수, 경과 시간, 진행 중인 이벤트 배너
- 코인 위에 참가자 이름 라벨. 코인이 겹치면 최상단 코인의 라벨만 그린다.
- 하단 컨트롤: 스킵 버튼 하나. 누르면 시뮬레이션을 빠르게 진행해 즉시 결과로 간다.
- 당첨 연출: 슬로우모션 → 풀스크린 오버레이 + 컨페티 + 이름 크게 표시 → "다시하기" / "참가자 수정"
- 사이트 디자인 토큰(`accent`, `card-bg`, `border`, `text-primary` 등) 재사용, 다크모드 대응
- 모바일: 세로 화면에서 판 전체가 보이도록 캔버스 비율 조정, safe-area 보정

## 7. 데이터 저장

없음. 전부 브라우저 세션 내에서만 동작한다. Supabase 연동, 결과 이미지 저장, 공유 링크는 이번 범위에서 제외한다.

## 9. 테스트

vitest 대상은 순수 모듈에 한정한다.
- `physics.ts`: 두 코인 충돌 후 운동량 보존, 벽 관통 없음, 푸셔가 코인을 앞으로 민다, 낙하선 통과 시 낙하 판정, 같은 시드로 두 번 돌리면 동일 결과
- `events.ts`: 시드 고정 시 이벤트 발생 시퀀스 재현, 막판 스퍼트가 임계 시각에 활성화, 특수 코인이 참가자 코인에 부여되지 않음
- `random.ts`: 같은 시드 → 같은 수열

Canvas 렌더와 React 컴포넌트는 단위 테스트하지 않는다.

## 10. 범위에서 제외

- 3D 렌더링
- 결과 저장·공유·리더보드
- 사운드 (초기 구현에서는 넣지 않는다)
- 참가자별 코인 개수 조절 (1인 1코인 고정)
