# 똥 말랑 (Ddong Mallang) 설계

경로: `/playground/ddong-mallang`

## 무엇인가

배를 보이고 누운 고양이가 전체화면에 뜬다. **배를 꾹 누르면 힘주기, 손을 떼면 심호흡**이다.
누르는 동안 5·4·3·2·1이 세지면서 초마다 다른 말이 나오고, 떼면 "심호흡하세요" 3·2·1이
세진다. 이걸 반복하다 다 끝나면 "다 쌌어요"를 누른다.

배변을 도와주는 장치다. 힘주기와 쉬기의 리듬을 화면이 잡아주는 것이 전부다.

주 사용 환경은 **모바일**이다. 한 손으로, 화면만 보면서, 조용히 쓴다.

## 왜 상태 머신을 따로 떼는가

이 앱의 로직은 전부 "지금 어느 단계이고, 남은 시간이 얼마이고, 입력이 들어오면 어디로
가는가"다. 그런데 그 입력은 포인터 이벤트에서 오고, 시간은 애니메이션 프레임에서 온다.
둘을 컴포넌트 안에 섞으면 5초가 실제로 5초인지, 떼는 순간 정확히 어디로 가는지를
브라우저를 띄워서 손으로 눌러봐야만 확인할 수 있다.

그래서 `session.ts`를 **React도 DOM도 모르는 순수 모듈**로 만든다. 받는 이벤트는 세 개뿐이다.

- `press` — 배를 눌렀다
- `release` — 손을 뗐다
- `tick(dt)` — `dt` 밀리초가 흘렀다

시간을 인자로 받으므로 테스트에서 5초를 기다릴 필요가 없다. `tick(5000)` 한 번이면 된다.
`gaebari-glare`의 `state.ts`와 같은 구조다.

## 단계

여섯 개다.

| 단계 | 화면 | 나가는 길 |
|---|---|---|
| `ready` | 시작 화면 | "시작하기" → `waiting` |
| `waiting` | "배를 꾹 눌러보세요" | `press` → `pushing` |
| `pushing` | 5·4·3·2·1, 초마다 다른 문구 | `release` → `breathing` / 0 도달 → `extra` |
| `extra` | 1·2·3… 버틴 초가 올라간다 | `release` → `breathing` |
| `breathing` | 3·2·1 "심호흡하세요" | 0 도달 → `waiting` / `press` → `pushing` |
| `done` | 축하 화면 | "다시 하기" → `ready` |

`done`으로는 `waiting`·`pushing`·`extra`·`breathing` 중 화면 구석의 "다 쌌어요"로 갈 수 있다.
`ready`에는 그 버튼이 없다 — 시작도 안 했는데 끝낼 수는 없다.

### 실패가 없다

`pushing` 5초를 다 못 버티고 손을 떼도 **그대로 `breathing`으로 간다.** 몇 초를 버텼는지
따지지 않고, 되돌리지도 않는다.

카운트를 온전히 채워야 성공으로 치면 게임이 되는데, 이건 게임이 아니다. 실제로 힘이
얼마나 들어가는지는 사람마다 다르고 그날마다 다르다. 변기에 앉아서 "실패했습니다"를
보는 것은 도움이 아니다. 그래서 **모든 릴리즈는 정상적인 진행**이다.

카운트를 다 채우고 끝난 경우에는 "잘했어요"를 얹는다.

못 채운 쪽에는 처음에 아무 말도 얹지 않기로 했다가, 다시 뒤집었다. 아무 반응이
없으면 "덜 한 것"이 그냥 없던 일이 되어 다음에도 같은 데서 멈춘다. 대신 지적이
아니라 권유로 말한다 — **"아쉬워요, 다음엔 끝까지 힘줘 봐요"**를 1.5초만 띄우고
평소의 "심호흡하세요"로 돌아간다. 실패로 되돌리지 않는다는 원칙은 그대로다.

### 5초를 넘겨서까지 누르고 있으면

`pushing`이 0에 닿아도 손이 배 위에 있으면 심호흡으로 밀지 않는다. 밀어버리면
손은 누르고 있는데 화면이 "배를 꾹 눌러보세요"를 띄우는 상태가 되어 고장으로 읽힌다.

대신 `extra`로 넘어가 **숫자가 1부터 거꾸로 올라간다.** 문구는 놀라다가 걱정하는
쪽으로 바뀌고(더 힘준다고? → 아직도?! → … → 무리하진 마세요), 마지막 문구에서
멈춘다. 손을 떼야 심호흡으로 간다. 여기까지 왔으면 5초를 채운 것이므로 칭찬이 붙는다.

### 심호흡 중에 누르면

받아준다. 즉시 `pushing`으로 가고 카운트가 새로 5부터 돈다.

다만 지시 문구 자리에 **"템포가 빨랐어요"를 1.5초간** 띄운다. 그 뒤에는 그 초의
평소 문구로 돌아간다. 숫자는 처음부터 새 힘주기 카운트를 보여준다.

무시하는 쪽도 생각했지만 — 쉬는 구간이 실제로 쉬어져야 하니까 — 배가 눌렸는데 화면이
반응을 안 하면 고장으로 읽힌다. 그리고 힘이 들어오는 타이밍은 사용자 몸이 정하는
것이지 화면이 정할 일이 아니다. 그래서 받아주고, 템포만 알려준다.

## 구성

```
src/app/playground/ddong-mallang/
  page.tsx            metadata + main
  session.ts          순수 상태 머신
  session.test.ts     vitest
  Cat.tsx             인라인 SVG 고양이 (표현 전용)
  DdongMallang.tsx    클라이언트 컴포넌트
  haptics.ts          navigator.vibrate 래퍼
```

`DdongMallang.tsx`가 유일하게 브라우저를 아는 층이다. 포인터 이벤트를 `press`/`release`로
바꿔 `session.ts`에 넣고, `requestAnimationFrame`으로 `tick`을 돌리고, 나온 상태를
`Cat`과 문구에 꽂는다.

`Cat.tsx`는 `mood`와 `strain`(0~1)만 받는다. 단계가 무엇인지, 몇 초 남았는지 모른다.
그래서 고양이 그림을 고치는 일과 로직을 고치는 일이 서로 안 건드려진다.

## 화면

상단에 큰 숫자, 그 아래 지시 문구, 그 아래 배를 보이고 누운 고양이 전신.

숫자를 배 위에 얹는 쪽도 검토했지만 — 누르는 지점에 있으면 시선이 안 분산된다 —
누르는 손가락이 숫자를 가린다. 상단으로 올린다.

전체화면은 `_shared/useFullscreen`을 재사용한다. `paper-plane`에서 떼어내 공용이 된 것을
그대로 쓴다.

고양이 표정은 단계에 매핑된다.

- `waiting` — 눈 반쯤, 편안하게
- `pushing`·`extra` — **세기(0~1)에 따라 이어서 변한다.** 눈이 점점 감기고, 볼이
  점점 붉어지고, 턱을 당기고, 앞발을 오므리고, 꼬리가 말리고, 배가 눌린다. 절반을
  넘으면 입이 앙다문 모양이 되고 막판에 눈썹이 뚜렷해진다. 눌렀다/안 눌렀다 둘로만
  나누면 5초가 그냥 정지 화면이 된다
- `breathing` — 눈 감고 입이 동그래진다
- `done` — 웃는 눈에 옅은 볼터치

`motion` 패키지가 이미 있어서 추가 의존성은 없다. 에셋도 없다 — SVG를 직접 그린다.

## 입력

`pointerdown` / `pointerup` / `pointercancel` / `pointerleave` 네 개로 마우스와 터치를
한 코드로 받는다. 뒤의 두 개가 중요하다 — 누른 채로 손가락이 배 밖으로 나가거나
전화가 오면 `pointerup`이 안 오고, 그러면 영원히 힘주는 중이 된다.

모바일에서 필요한 것들.

- `touch-action: none` — 누르는 중에 페이지가 스크롤되지 않게
- `user-select: none` — 길게 눌렀을 때 텍스트가 선택되지 않게
- 컨텍스트 메뉴 차단 — 길게 누르면 뜨는 것
- `fixed inset-0` — 사이트 레이아웃(헤더 + `<main>` 여백)에 갇히면 높이가 뷰포트를
  넘겨 아래 버튼이 밀려난다. `marble-drop`과 같은 방식으로 뷰포트를 뜯어낸다
- 고양이를 담은 flex 아이템에 `min-h-0` — 없으면 SVG의 내재 높이가 그 아이템의
  자동 최소 높이가 되어, 화면이 짧을 때 아래 버튼이 통째로 밀려나 잘린다
- `viewport-fit=cover` + `env(safe-area-inset-bottom)` — 전체화면에서는 페이지가
  화면 맨 아래까지 차지해서, 홈 인디케이터·제스처 바가 하단 버튼을 덮는다

## 햅틱

`navigator.vibrate`를 쓴다. 카운트마다 짧게 톡, 힘주기 카운트를 다 채우면 두 번,
축하할 때 패턴.

소리는 넣지 않는다. 공용 화장실에서 숨소리가 나오면 못 쓴다.

iOS 사파리는 Vibration API를 지원하지 않는다. **되게 만들 방법이 없으므로 조용히
무시되게 둔다.** `haptics.ts`가 미지원을 감지해 no-op이 되고, 경고도 안내도 띄우지
않는다. 화면과 문구만으로 앱이 온전히 동작해야 한다는 뜻이다 — 진동은 어디까지나 덤이다.

## 축하 화면

"다 쌌어요"를 누르면 `done`이다. 보여주는 것은 **총 걸린 시간과 힘준 횟수** 두 개뿐이다.

- 총 걸린 시간 — "시작하기"부터 "다 쌌어요"까지의 누적된 tick 시간. 화면이 렌더되지 않은 시간(화면 잠금, 앱 백그라운드)은 세지 않는다.
  당신을 코칭하지 않던 시간은 앱이 주장할 시간이 아니기 때문이다.
- 힘준 횟수 — `pushing`에 진입한 횟수. 5초를 채웠는지는 세지 않는다.
- **템포 기록** — 힘주기 한 번마다 막대 하나. 5초 자리에 세로선을 긋고, 채운 것과
  못 채운 것을 색으로 가른다. 숫자만 나열하면 "3.2초, 5.0초, 0.9초"가 그냥 숫자라
  리듬이 안 읽히는데, 막대로 세우면 뒤로 갈수록 짧아지는 흐름이 한눈에 보인다.

기록을 저장하지 않는다. 배변 기록은 민감한 데이터인데 이 앱이 그걸 들고 있을 이유가
없다. 새로고침하면 사라진다.

## 테스트

`session.ts`가 순수 함수라서 로직 전체가 단위 테스트로 덮인다.

- `pushing` 5초 소진 → `extra`, 손을 떼야 `breathing`이고 그때 "잘했어요"가 선다
- `pushing` 중 조기 `release` → `breathing`, 칭찬 대신 "아쉬워요" 한마디가 1.5초 뜬다
- 초마다 문구가 바뀌고, 다섯 초가 서로 다른 말이다
- 힘주기 한 번마다 버틴 시간이 템포 기록에 쌓이고, 누른 채로 끝내도 안 빠진다
- `tick`이 여러 번 쪼개져 들어와도 누적이 맞는다 (`tick(2000)` 세 번 = `tick(6000)`)
- `breathing` 중 `press` → `pushing`, 카운트가 5로 리셋되고 "템포가 빨랐어요" 플래그가 선다
- "템포가 빨랐어요"가 1.5초 뒤 사라진다
- `breathing` 3초 소진 → `waiting`
- 힘준 횟수가 사이클마다 증가한다
- `done`의 총 시간·횟수 집계가 맞는다
- `ready`에서 `press`는 아무 일도 하지 않는다

`Cat.tsx`와 `DdongMallang.tsx`는 단위 테스트하지 않는다. 전자는 SVG 좌표뿐이고 후자는
브라우저 배선뿐이어서, 테스트가 구현을 복사하는 것 말고 할 일이 없다.
